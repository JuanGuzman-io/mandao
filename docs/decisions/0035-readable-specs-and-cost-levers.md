# 0035 — Readable spec documents, a real lite, Leader scripts, approvals and recorded premises

**Status:** Accepted · 2026-10-20

The MDO-0004–0006 runs showed two costs: documents that read like audit logs (and that every command
loads), and model sessions spent on mechanical work. This ADR records what was approved after MDO-0006.

## 1. Spec documents for people (readability pass)

`rules/spec-docs.md` holds the principles; the templates are skeletons.
- One question per document, a 2–3 line summary under the title, evidence at the end or in `<details>`,
  short table cells, each fact in one document (the others link to it), no history and no HTML comments
  with content.
- Machine files live in `_log/` (`execution.md`, `progress.yml`, `reviews/`, `mutations/`, `gates/`,
  `premises/`, `approvals.yml`). Specs started before keep them in the root; every reader and writer
  follows the file where it is (`logPath`), so a spec is never split.
- `close-summary.md` is generated with the links to what the close produced.
- `quickstart.md` only for behavior a user or a PO can see, about 400 tokens at most.
- `tasks.md` in two layers: an Overview by acceptance criterion with a checkpoint per group, generated by
  `mandao run tasks --index --write` and checked against the details; Details with What, Done when (at
  most 5 bullets), Notes, and a YAML block without prose. `test_levels` (`unit | e2e | eval | none` per
  scenario) and `evidence` (`tdd | mutation | none`) replace `tests`, `dod` and `characterization`, which
  older specs still use. The validator rejects titles with paths, prose in YAML and missing levels.

On MDO-0005 the pass cut the documents from 15,497 to 13,963 tokens (−10%) and what one pass through the
flow loads from 46,715 to 38,415 (−18%); `tasks.md` alone fell 42%.

## 2. A lite that removes steps

At lite depth `specify` writes `story.md` and `spec.md` (requirements, design with High premises only,
and up to 3 tasks inline) in one session with one approval; `clarify` runs only when something is open.
Parsers, trace, the task validator, the checkpoint, impacts and the diagram stamp read the same sections
from `spec.md` (`docPath`).

## 3. Leader scripts

`mandao run step` (checkpoint + next action + brief when delegating), `mandao run gates` (pass/fail and
the failure excerpt; full output in `_log/gates/`), `mandao run review-pack` (one file the Reviewer reads)
and `mandao run implement-summary` (the final report from the log and git). `mandao run` prints compact
JSON (`MANDAO_JSON=pretty` for people).

## 4. `mandao approve`

`mandao approve <spec> <story|design|spec|tasks|close>` checks the gate the command would apply, sets the
status, records who (git `user.name`) and when in `_log/approvals.yml`, and makes the spec commit, with no
model session. For close it records the approved items; the close session applies them. After approving,
the recommended next step is the next command in the same session (context and prompt cache reused).

## 5. Premises verified only by a recorded run

`mandao run premise <spec> <Pn> -- <command>` runs the proof in the worktree with a timeout, through the
queue and the resource budget, and records it in `_log/premises/`. `trace` reports `PREMISE_UNPROVEN` for
a High premise with neither a recorded run nor `UNVERIFIED`, and `approve design|spec` refuses it. `tasks`
puts the run of an `UNVERIFIED` High premise into the Done when of the first task that can run it (MDO-0006
Kaizen).

## Also fixed (MDO-0006)

`tasks` and `verify` commit their documents; red and mutation evidence record the agent Mandao routed the
task to (`testWriter`), never a name typed by the model; the quick log keeps review notes in the Review
column; close lists a write the harness refuses as pending, with its diff.

## Command statuses

`implement`, `close` and `quick` are stable after the MDO-0006 run.
