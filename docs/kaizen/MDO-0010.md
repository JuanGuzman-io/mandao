## Learn

<a id="l1"></a>
1. **The task's "Done when" carried a subset of the spec, and the FAILs landed on the rest.**
   - **What happened:** each of three FAILs was a rule written in `spec.md` that was missing from that task's "Done when":
     - **T1:** FR-5 names `/mandao-implement` on draft tasks, and AC-5/C1 names "a critical Consistency Check finding". The "Done when" listed neither, so `approve tasks --by-running` approved past a critical OPEN.
     - **T2:** FR-3 and the task's "What" name `approve`, `run step` and `implement-summary`, but the "Done when" tested only `approve`. `run step` kept the old advice.
     - **T3:** D2's "Rejected" line forbids a per-harness `mandao:if` block. No "Done when" item said so, and the texts gained about 30 copied resume commands.
   - **Root cause:** `tasks` writes "Done when" as a summary of the FRs. The implementer and its red tests aim at the "Done when", not at every entry point and every list item in the FR. A decision's "Rejected" option is not stated as a must-not, so it can be built.
<a id="l2"></a>
2. **This spec's own first cost record double counts MDO-0009.**
   - **What happened:** `mandao run cost MDO-0010 --record --command specify` logged 27.08 USD. The session had already recorded MDO-0009 in another spec's file, and `sessionDelta` searched only the file it writes.
   - **Root cause:** the same one T4 fixed for quick (D5, P4). The fix applies forward. The record stays as evidence, because logs are never edited by hand, so this spec's total and the cross-spec average stay overstated by the MDO-0009 share.
<a id="l3"></a>
3. **A task added after specify had no scenarios, so trace reports it untested.**
   - **What happened:** the maintainer added T5 after the T1 and T2 reviews, with `scenarios: []` and `test_levels: {}`. Its "Done when" items are tested in `next.test.ts`, but `verify-plan` reports `UNTESTED T5`. TDD did not require a red row for it, and the T5 Reviewer noted the red claim as unverified.
   - **Root cause:** adding a task does not go through clarify, so nothing turns its "Done when" into scenarios with clause ids.

## Standardize

The maintainer approved both in the close session. They are applied in `core/commands/tasks.md` §2,
with `mandao sync` and the regenerated diagrams.

1. "A task's Done when lists every entry point, list item and clause of the FRs it serves, and states each rejected option of its decisions as a must-not."
2. "A task added after specify declares scenarios through `/mandao-clarify`, never `scenarios: []`."

The session-cut proposals above are not applied: the maintainer decides on them separately (ADR 0038).
