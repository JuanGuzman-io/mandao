## Learn

1. **The lite template hides impacts from `impacts`.** `core/templates/shared/spec/spec.md` has only
   `## Risks and impacts`, so the proposal to update `standards.md:23-25` was written as a bullet
   there (`spec.md`, Risks and impacts) and `mandao run impacts MDO-0007` returned
   `{"constitution":[],"product":[]}`. Close found it only by reading the spec.
2. **The red run came after code the tests call.** The Leader's T2 brief listed "write the exception
   helper and the guard" before "record red", so the red run named only one of the two offenders the
   task named, and S-4.1 was never seen failing (`_log/execution.md`, T2 rows).
3. **Related-test selection missed the tree-scanning guard.** `vitest related` follows imports;
   `test/unit/architecture.test.ts` reads `test/` from disk, so the T1 gate ran 1 of 54 files and
   skipped the guard the T1 edit was made to satisfy (`_log/gates/T1-1.md`, "Affected 1 of 54"). The
   Leader ran it by hand.

## Standardize

All three approved at close (`mandao approve MDO-0007 close`, items 3–5); applied in a follow-up
change, not in this close.

1. `core/templates/shared/spec/spec.md`: add `## Constitution Impact`, `## Product Impact` and
   `## Module Docs Impact` after `## Risks and impacts`, so lite specs feed `mandao run impacts`.
2. `core/commands/implement.md` step 3: "The red run is recorded before any code of the task,
   including helpers the new tests call."
3. `core/templates/shared/rules/test-policy.md` § Which tests run: "Tests that scan the tree by path
   (architecture guards) run whenever a file under the folder they scan changes."
