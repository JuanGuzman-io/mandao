## Learn
1. **verify and release-status disagree on the AC row format** (evidence: `verify-report.md` labels its
   rows `AC-1 main`, `AC-2 main`…, all with Result PASS; `verifyResults` in `src/spec/release.ts:21-22`
   keys on the whole first cell, so `mandao run release-status MDO-0004` reports every AC `partial`,
   "not in verify-report.md"). The template's `AC / clause` column does not say the id must stand alone.
2. **impacts reads only the first line of a bullet and skips prose** (evidence: `mandao run impacts
   MDO-0004` returned `the row "…" can name` and `add "commands with --json print exactly one JSON
   document` — both cut mid-sentence — and `product: []`, while `design.md:78-79` proposes a
   capability-map row as a paragraph).
3. **The design diagram was never stamped** (evidence: `design.md` `## Diagram` holds only the stamp
   comment; `mandao run diagram-drift MDO-0004` fails with "design.md has no diagram with a structured
   graph"). Nothing in specify or tasks stopped an approved design without a diagram.

## Standardize
All three approved by the maintainer's delegate (2026-10-20) and assigned to the maintainer, to be
implemented with tests in Mandao's own code and templates, outside this close (nothing in `core/` or
`src/` was edited here).

- `.mandao/templates/app/spec/verify-report.md`: under the AC table, "the first cell is the bare id
  (`AC-n` or `AC-n/Cn`); put qualifiers in the Tests cell" — approved, assigned to the maintainer.
- `src/spec/release.ts` `impactItems`: keep a bullet's continuation lines and read a non-bullet
  paragraph as one item — approved, assigned to the maintainer.
- `/mandao-specify`: the Consistency Check flags an empty `## Diagram` at standard and full depth —
  approved, assigned to the maintainer.

For this close only, the four AC rows in `verify-report.md` were relabelled to the bare id, with the
qualifier moved into the Tests cell (approved: option 1a). No result changed; `release-status` then
reported all four ACs `met`.
