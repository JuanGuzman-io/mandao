## Learn

<a id="l1"></a>
1. **A task that edits `core/` was done without `mandao sync`.** T3 and T4 changed
   `core/commands/close.md` and the Kaizen template. Their tests prove that a sync produces the new step,
   but this repo's own generated files were not regenerated. Verify blocked on it, and a separate sync
   commit (7af5b78) fixed it. T3's Reviewer noted it as an advisory (`_log/execution.md`, T3 PASS row).
   Advisories never block, so the rule has to sit with the task.
<a id="l2"></a>
2. **The helpers run the installed Mandao, not the branch.** `.mandao/bin/mandao.mjs` resolves to the
   global `mandao` (0.1.0, `~/.nvm/.../lib/node_modules/mandao`). So on this branch `run kaizen MDO-0008`
   returned no `sessions` and `run kaizen-compare` no `sessionCut`, although close step 1 asks for both.
   Only `node dist/cli.js` showed them. Root cause: a spec that adds a helper output is dogfooded
   through a runner built before the spec, and both report the same version, so nothing flags it.
<a id="l3"></a>
3. **A high-risk advisory passed the review.** T1's Reviewer passed attempt 3 with "A1 high: gray-matter
   default engines eval ---js front matter" as an advisory. The architecture gate then failed it, which
   took a fourth attempt (`_log/execution.md`, T1 rows of 2026-10-21). Root cause: the T1 brief did not
   name `src/engine/frontmatter.ts` as the only front-matter reader, and the Reviewer then treated a
   `high` finding as advice, not a FAIL.

## Standardize

The maintainer approved all three at close (`mandao approve MDO-0008 close`). Items 1 and 2 are
applied in a follow-up change, not in this close. Item 3 is already applied on main.

1. `core/commands/implement.md`, task done: "A task that edits `core/` runs `mandao sync` and commits
   the generated files with the task; only the Reviewer's blocking findings become a task or block the
   checkpoint, and advisories go to `execution.md`, the backlog or Kaizen." (Amended at approval: advisories never block.)
2. `AGENTS.md`, Mandao section: "Dogfooding: `mandao run` uses the installed Mandao; to measure a
   helper this branch adds or changes, run `node dist/cli.js run …` after `npm run build`."
3. `core/personas/reviewer.md` (verdict rules): "A `high` security finding is a FAIL, never an advisory."
   Applied on main by ADR 0039 (`docs/decisions/0039-rules-enforced-by-scripts.md`) and
   `core/personas/reviewer.md`. Not edited again.
