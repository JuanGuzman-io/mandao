## Learn
1. **A premise checked only by searching for keywords was wrong, and it blocked verify** (evidence:
   design P5 claimed that only three files create temp folders, based on a `mkdtemp|tmpdir` search on
   90b3307. The D6 run at verify found `scripts.test.ts:44-49` and `characterization.test.ts:74`
   writing next to their workspace through `join(root, '..', …)`; see `verify-report.md` History, PB-1
   and PB-2, and CC-V1). P5 had impact High and only at-source evidence. This is the same root cause as
   MDO-0005 lesson 2. The rule approved there has not been implemented yet, and it would have caught
   this.
2. **Checking the outcome found what the text guard could not** (evidence: the D6 run with a
   sentinel-seeded `TMPDIR` found both leaks; the FR-5 text guard passed them, CC-V2). Even after
   widening, the guard misses `join(a, b, '..')`, `resolve(x, '..')` and `dirname(makeTree(…))`
   (T3 Reviewer advisory, `execution.md`). Today, AC-1 is protected only by a manual run at verify.
3. **The check that verify needed was blocked by permissions** (evidence: in the first verify, the
   forced-failure D6 run was "denied by the permission system three times in this non-interactive
   session", leaving AC-1/C1 unverified; see `verify-report.md` History). The design prescribed an
   ad-hoc command line. Nothing prepared it ahead of time, so the permission allowlist could not
   cover it.

## Standardize
All three were approved by the maintainer's delegate (2026-10-20, MDO-0006 close) and assigned to the
maintainer. They will be implemented with tests outside this close: Mandao's code, CI and templates
are not edited here.

- `.github/workflows/` `check` job: run `npm test` with `TMPDIR` set to a fresh folder, then fail if
  anything other than `node-compile-cache/` is left in it. This turns D6 into a permanent check and
  covers lessons 2 and 3. Approved, assigned to the maintainer.
- `vitest.config.ts`: pin `sequence: { hooks: 'stack' }` with a comment naming MDO-0006 AC-2/C1, so a
  later change to hook order cannot remove workspaces before the file's own `afterAll` runs (T1
  Reviewer advisory). Approved, assigned to the maintainer.
- Raise the priority of the premise-ledger rule approved in MDO-0005 (a premise with impact `High`
  needs "as run" evidence, or is marked `UNVERIFIED`), and extend it: a claim that something happens
  in "only" a given set of places needs outcome evidence, not a keyword search. Approved, assigned to the maintainer.

## Addendum — could the rework have been caught earlier? (2026-10-20, after the close)

**Why verify blocked.** Design premise P5 ("only `makeTree` and the commitlint test create folders in the
temp folder") was checked with a keyword search for `mkdtemp|tmpdir`. Two tests wrote next to their
workspace through `join(root, '..', …)` and never matched. The only check that observes the outcome, a
full `npm test` with a fresh `TMPDIR` (design D6), was scheduled for verify.

**Where it could have been caught.**
- **specify:** P5 was a High-impact "only these places" claim; it was proven by search, not by a run.
  The approved premise rule (MDO-0005) would have flagged it as unproven.
- **tasks:** the planner repeated the same search ("a search of `test/` and `src/` confirms it"), so it
  added no evidence. It could have made the D6 run the `verify` command of T1, the first task able to run
  it.
- **implement review:** no. The Reviewer sees the task's diff and brief; the leaking lines were in files
  the tasks did not touch, so nothing in its input pointed at them.

**Proposed standardization (for approval):** when a High premise is `UNVERIFIED` and its proof is a run,
`tasks` schedules that run as the `verify` command of the first task that can execute it (or records it
with `mandao run premise`), so a false premise fails in implement, not in verify. Estimated saving here:
the rework loop, 2.71 USD of 10.69.
